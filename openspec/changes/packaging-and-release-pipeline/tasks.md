Estas tareas asumen las opciones recomendadas; si el dueño elige otra, actualizar specs y tareas (`/opsx:update`) antes de codear.
> **Acciones que publican = autorización explícita del dueño en ese momento**: push de cualquier rama, abrir/cerrar PRs, disparar `release.yml`, crear tags o releases, publicar. El agente NUNCA publica el release ni cambia la configuración del repo (rulesets, Actions, permisos).
> **Strict TDD, sin excepciones** en cada tarea que agrega comportamiento verificable por test: (1) **RED**: escribir el test y **ejecutarlo**, copiando en `design.md` §Apply notes el comando y las líneas del fallo **antes de escribir código o configuración de producción**; (2) **GREEN**: el mínimo cambio, ejecutando; (3) **TRIANGULATE**: al menos un segundo caso con entradas y salidas distintas; (4) **REFACTOR** con tests en verde. En Rust un error de compilación vale como RED **solo** si es por el símbolo nuevo que el test referencia. Una tarea sin su salida RED anotada no se marca `[x]`. Sin aserciones triviales.
> Comandos desde la raíz del repo, **siempre desde una terminal NO elevada**. Rust: `cargo test --manifest-path src-tauri/Cargo.toml --locked <filtro>` (PowerShell, o Git Bash con `export PATH="$HOME/.cargo/bin:$PATH"`). Frontend: `npm test`, `npm run build`.
> Rama `feat/packaging-and-release-pipeline` desde `main` con C-12 fusionado (D-25). Partes para commits: **Parte 1** = grupos 1–3, **Parte 2** = grupos 4–7, **Parte 3** = grupo 8, **Parte 4** = grupo 9, **Parte 5** = grupo 10. Sin dependencias nuevas de la app: `package-lock.json` y `src-tauri/Cargo.lock` no deben cambiar (salvo en las ramas descartables `ci-gate/*`). No tocar código de la app (`src/`, `src-tauri/src/`), ni CSP, capabilities o plugins. Nunca versionar `.engram/` ni `.atl/`. Skills: `cicd-dev`, `tauri-v2`, `tauri-security`, `rust-testing`, `rust-best-practices`, `security-debugger` (si algo falla en el runner).
